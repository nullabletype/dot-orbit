How work is organised

Projects, Categories and Today

Tasks can sit inside a Project or stand alone. Categories group both. Today is a smaller list that you choose from the same manual order used by the Backlog.

01 / PROJECTS

Keep related Tasks together

A Project works out its progress from the Tasks inside it. Each Task can still be completed, reordered or dated on its own.

  • Tasks can stand alone without a Project
  • Add a Task directly from a Project
  • Category and Project identity pills take you back to their source
02 / CATEGORIES

Categories cross Project boundaries

A Category can contain Projects and standalone Tasks. Tasks inside a Project inherit its Category unless you choose something else.

  • Projects and standalone Tasks appear in separate sections
  • Names stay visible beside their colour markers
  • Category relationships can be changed in the app
Work views

Four ways to see the same Tasks

Today and Backlog share one manual order. Upcoming groups incomplete Tasks by due date. Completed keeps recent results nearby, while Archive holds older Projects and Tasks without putting them back into active work.

Provider-neutral agent handover

Agent proposals stop for local review.

dot-orbit does not choose or contact an AI provider. You decide what context leaves the app. Imported work is checked against current local state and shown for review before anything changes.

  1. 01 / CONTEXT

    Choose the context

    New work needs no workspace access. For changes involving existing work, inspect and copy a bounded Planning snapshot. Archived and binned work stays out, though visible Category and Participant names may still reveal context.

  2. 02 / REVIEW

    Inspect the proposal

    Type, paste, load, drop or receive a proposal through local MCP. dot-orbit checks it against current local state and shows what it would add or change.

  3. 03 / APPLY

    Apply it yourself

    Apply needs a separate confirmation. dot-orbit creates an encrypted recovery point first, then applies the proposal as one change. The agent cannot approve its own work.

Local MCP

MCP connects through the desktop app

An MCP host launches dot-orbit’s packaged stdio adapter. It reaches the unlocked desktop through private same-user IPC, with no network listener. The adapter cannot open the workspace, unlock it or receive encryption material.

  1. 01MCP hostLocal client process
  2. 02stdio adapterNo workspace or key material
  3. 03Private brokerSame-user, scoped session
  4. 04Local reviewHuman approval required

Grant read, submit, or both for each client. Read access returns only its named current-work scope. Submission enters the same in-app Review flow as manual handover; it never grants autonomous Apply.

Independent controls

Either setting can shut MCP down.

AI features and Local MCP have separate device-local switches. Both start off. New or changed access needs approval for its exact scopes; an exact remembered match can reconnect under the policy you kept.

Enable AI featuresOff by defaultGlobal control for every agent-interchange feature.
Enable Local MCPOff by defaultIndependent control for the local broker and MCP sessions.

Kill switch: turn off either gate, lock the workspace, exit dot-orbit, or revoke the adapter. The broker closes active sessions and invalidates live capabilities. Remembered approval retains policy only—never a live connection.

Your disclosure boundary still matters. Clipboard handover writes sensitive unencrypted text only after confirmation. Approved MCP read scopes return plaintext context to the MCP host. dot-orbit does not contact an AI provider, but the host may use one under its own data-handling policy.

Local by design

Your task list is not a service.

Your workspace and recovery backups are encrypted with your passphrase. There is no account system or built-in sync. If you want an off-device recovery copy, you choose where it goes.

1

Passphrase access

Your passphrase opens the encrypted workspace stored locally on your desktop. There is no remote account recovery.

2

Local workspace

You choose the workspace file. dot-orbit remembers its location on this device; Projects, Tasks, Categories, Today, and history stay inside it.

3

Encrypted backups

Recovery copies remain encrypted. Their destination can be local or a folder managed by an external sync service.
