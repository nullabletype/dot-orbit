# Dependency and runner baseline

Checked: 2026-10-21

Review by: 2026-10-29

This file records the support check for the runnable desktop shell, encrypted workspace lifecycle, and self-contained release packaging. Package lock files remain the reproducible record of the complete transitive graph.

## Runtime and SDK

- .NET 10 is the active LTS release through 2028-11-14. The repository pins SDK 10.0.402, which includes the current 10.0.13 runtime security patch (verified 2026-10-21 against the [official .NET 10 release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json)). Source: [.NET support policy](https://dotnet.microsoft.com/en-us/platform/support/policy) and [.NET 10 downloads](https://dotnet.microsoft.com/en-us/download/dotnet/10.0).
- `net10.0` is the only target framework in this slice. Preview SDKs and runtimes are not used.

## Direct packages

- Avalonia desktop, Fluent theme, Inter font, and headless xUnit integration are pinned to 12.1.3. Avalonia 12.1 lists Windows 11 24H2, macOS 26, Ubuntu, and Debian 13 among its supported desktop targets. Source: [Avalonia supported platforms](https://docs.avaloniaui.net/docs/supported-platforms) and the [Avalonia.Desktop package](https://www.nuget.org/packages/Avalonia.Desktop/12.1.3).
- `Bebop.JsonSchema` is pinned to 1.1.0, the current MIT-licensed release. It directly targets .NET 10, has no runtime dependencies on that target, implements JSON Schema 2020-12, and provides the local-only in-memory registry used for the agent-interchange schema catalogue. The remote-resolving registry is not used. Source: [Bebop.JsonSchema 1.1.0](https://www.nuget.org/packages/Bebop.JsonSchema/1.1.0) and the [Bebop.JsonSchema repository](https://github.com/cptjazz/Bebop.JsonSchema).
- Markdig is pinned to 1.4.0, a BSD-2-Clause release published on 20 September 2026 with direct .NET 10 support. dot-orbit consumes its CommonMark parser and syntax tree only; the application owns URI allow-listing, raw-HTML removal, remote-image placeholders, preview rendering, and clipboard serialisation. Source: [Markdig 1.4.0 release](https://github.com/xoofx/markdig/releases/tag/1.4.0) and the [Markdig package](https://www.nuget.org/packages/Markdig/1.4.0).
- `xunit.v3.mtp-v2` is pinned to 3.2.2. The explicit package selects MTP v2 while retaining the xUnit 3.2 discovery API required by Avalonia.Headless.XUnit 12.1.3. Its minimum MTP 2.0.2 dependencies are legacy, so central transitive pins keep the platform, MSBuild, telemetry, and TRX-abstractions packages together on the current 2.5.1 line. xUnit 4.0.2 also uses MTP v2, but remains incompatible with Avalonia's headless discoverer because it changes that API; upstream tracks the resulting `MissingMethodException`. Revisit the framework pin when Avalonia publishes compatible headless integration. Source: [xUnit Microsoft Testing Platform version selection](https://xunit.net/docs/getting-started/v3/microsoft-testing-platform), [xUnit 3.2.2 MTP v2 package](https://www.nuget.org/packages/xunit.v3.mtp-v2/3.2.2), [Microsoft Testing Platform](https://learn.microsoft.com/dotnet/core/testing/microsoft-testing-platform-intro), [xUnit 4.0.2 release](https://xunit.net/releases/v3/4.0.2), and [Avalonia issue #22072](https://github.com/AvaloniaUI/Avalonia/issues/22072).
- `Microsoft.Data.Sqlite.Core` is pinned to 10.0.13, the current stable .NET 10 servicing release (verified 2026-10-21). The `.Core` package is required so the application can supply one SQLite native bundle rather than pulling in the default SQLitePCLRaw bundle. Source: [Microsoft.Data.Sqlite.Core 10.0.13](https://www.nuget.org/packages/Microsoft.Data.Sqlite.Core/10.0.13).
- `SQLite3MC.PCLRaw.bundle` is pinned to 2.4.0, the retained NuGet release, published in July 2026 with SQLite3 Multiple Ciphers 2.4.0 based on SQLite 3.53.4. It is MIT licensed and supplies the native sqleet ChaCha20-Poly1305 implementation for the supported desktop runtimes. Source: [SQLite3MC.PCLRaw.bundle 2.4.0](https://www.nuget.org/packages/SQLite3MC.PCLRaw.bundle/2.4.0) and [SQLite3 Multiple Ciphers sqleet parameters](https://utelle.github.io/SQLite3MultipleCiphers/docs/ciphers/cipher_chacha20/).
- The upstream SQLite3 Multiple Ciphers and .NET bundle have since released 2.6.1. The retained 2.4.0 pin and the security-relevant hardening in 2.6.0 require the explicit review below.
- Central package management and per-project `packages.lock.json` files pin the complete graph. Root `NuGet.Config` clears inherited package and audit sources, permits only NuGet.org, and maps all packages to that source. NuGet audit is enabled for all dependencies and vulnerability severities fail the build.
- The repository gate parses the JSON reports from `dotnet package list --project DotOrbit.slnx --vulnerable --include-transitive` and the separate `--deprecated` query after locked restore. A command failure, invalid report, vulnerability, or deprecation fails the gate. NuGet reported no known vulnerable or deprecated direct or transitive packages on 2026-10-21. Transitive packages inherit their support boundary from the current Avalonia and xUnit release lines and must be rechecked with those direct dependencies.

## Continuous integration

The release control uses Node's built-in HTTPS and stream implementations to call GitHub's versioned REST API; it adds no CLI or npm dependency. Node 24.21.0 is retained in the supported Node.js 24 line, which entered maintenance on 2026-10-20 and reaches end of life on 2028-04-30. The reviewed latest release is 24.22.0; its release catalogue marks `security: false`. Source: [Node.js 24.21.0 release archive](https://nodejs.org/en/download/archive/v24.21.0) and [Node.js release schedule](https://github.com/nodejs/Release#release-schedule).

- Release packaging uses `macos-26` for Apple Silicon and `macos-26-intel` for Intel. The runner-images catalogue lists those as the current macOS 26 ARM64 and x64 labels respectively.
- `actions/checkout` is pinned to the full commit SHA for v7.0.1.
- `actions/setup-dotnet` is pinned to the full commit SHA for v6.0.0 and installs SDK 10.0.402 exactly.
- `actions/setup-node` v7.1.0 is pinned to commit `949feb2413d6458794dcd2491c4babbbce0c15c1` and installs Node.js 24.21.0 exactly. Source: [actions/setup-node v7.1.0](https://github.com/actions/setup-node/releases/tag/v7.1.0).
- Admitted `main` and version-tag packages use `actions/upload-artifact` v7.0.1 pinned to commit `043fb46d1a93c77aae656e7c1c64a875d1fc6a0a`. This uses the supported Node 24 runtime; pull-request and manual runs never execute the upload step. Source: [actions/upload-artifact v7.0.1](https://github.com/actions/upload-artifact/releases/tag/v7.0.1).

This uses the supported Node 24 runtime and downloads only the four artifacts created in the same workflow run, with decompression disabled so the validated ZIP and tar-gzip files remain the release assets. Source: [actions/download-artifact v8.0.1](https://github.com/actions/download-artifact/releases/tag/v8.0.1).
- CodeQL retains the v4.38.2 action pinned to commit `2892aa5e19bbd11bc0cff5427e3b750a04d9e3c2` and analyzes C# on pull requests, pushes to `main`, manual dispatch, and the weekly security schedule. Source: [CodeQL Action v4.38.2](https://github.com/github/codeql-action/releases/tag/v4.38.2).
- The required Build workflow performs locked restore, formatting verification, Release build, and tests. It uploads no artifacts.
- The same explicit matrix launches the real Release-built desktop application. Linux uses the `xvfb` package included in the pinned Ubuntu 24.04 runner image; macOS and Windows use their native desktop environments. The smoke runner adds no package or action dependency and uploads no artifacts.
- The native journey locates standard Avalonia controls by their automation IDs and checks their built-in automation peers before routing keyboard input. Avalonia exposes those peers through UI Automation on Windows, NSAccessibility on macOS, and AT-SPI2 on Linux. Source: [Avalonia accessibility](https://docs.avaloniaui.net/docs/app-development/accessibility) and the [Ubuntu 24.04 runner software inventory](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md).

## First-release operating systems

Checked: 2026-10-06. The supported set follows DESK-004 and ADR 0002: serviced Windows 11 releases, current macOS releases covered by Avalonia, Ubuntu LTS, and current Debian stable. A host outside this set may happen to launch the application, but that does not make it supported:

- Serviced Windows 11 release and edition combinations available on x64. As of the check date this includes 23H2 Enterprise and Education, 24H2, 25H2, and 26H2 while each remains in Microsoft servicing. Windows 11 26H1 is ARM64-only and is outside the fixed `win-x64` first-release matrix. The release gate must re-evaluate the list against the Home/Pro and Enterprise/Education lifecycle tables rather than treating a Windows version as supported after its applicable edition reaches end of servicing. Source: [Avalonia supported platforms](https://docs.avaloniaui.net/docs/supported-platforms), [Windows 11 release information](https://learn.microsoft.com/windows/release-health/windows11-release-information), [Windows 11 Home and Pro lifecycle](https://learn.microsoft.com/lifecycle/products/windows-11-home-and-pro), [Windows 11 Enterprise and Education lifecycle](https://learn.microsoft.com/lifecycle/products/windows-11-enterprise-and-education), and [Windows 11 26H1 supported processors](https://learn.microsoft.com/windows-hardware/design/minimum/supported/windows-11-26h1-supported-processors).
- macOS 14 Sonoma, macOS 15 Sequoia, and macOS 26 Tahoe on x64 and arm64 where Avalonia lists that architecture. Avalonia currently lists macOS 26 as Tier 1 and macOS 14 and 15 as Tier 2. A later macOS version is not supported until Avalonia lists it and release verification passes there. Source: [Avalonia supported platforms](https://docs.avaloniaui.net/docs/supported-platforms).
- Ubuntu 24.04 LTS on x64 with X11. Canonical maintains 24.04 LTS through May 2029 and Avalonia lists Ubuntu 16.04 through 24.x as Tier 2. Ubuntu 26.04 LTS is maintained by Canonical but is not in Avalonia's current Tier 1 or Tier 2 table, so it is not a first-release target. Source: [Ubuntu 24.04 release notes](https://documentation.ubuntu.com/release-notes/24.04/) and [Avalonia supported platforms](https://docs.avaloniaui.net/docs/supported-platforms).
- Debian 13 Trixie on x64 with X11. Debian 13 is the current stable release and Avalonia lists it as Tier 1. Source: [Debian releases](https://www.debian.org/releases/) and [Avalonia supported platforms](https://docs.avaloniaui.net/docs/supported-platforms).

The release archives map to this set as `win-x64`, `linux-x64`, `osx-x64`, and `osx-arm64`. The hosted matrix proves those runtime and architecture boundaries, but Windows Server 2025 is not Windows 11, Ubuntu 24.04 is not Debian 13, and one macOS runner does not cover every supported macOS release. Supported-release evidence therefore also requires dated Windows 11, macOS 14 and 15, and Debian 13 checks outside the hosted runner matrix. A newer but unlisted host result, such as macOS 27, is diagnostic only and does not expand the support set.

## Packaging tools

- The repository packager targets the pinned .NET 10 SDK and uses only supported base-class-library APIs for Zip, POSIX tar, GZip, SHA-256, and JSON. It introduces no additional package dependency or floating host tool.
- Package restore is locked for all four explicit runtime identifiers. The final archive contains one self-contained executable plus the repository licence, third-party notices, and the generated integrity manifest.
- Relevant pull requests and manual runs assemble, inspect, extract, and run every archive on its matching architecture without retaining artifacts. Pushes to `main` and admitted version tags retain only the final validated archives, using the action pin recorded above. A valid tag stamps its SemVer into the executable and manifest; the draft job uses the pinned Node runtime and GitHub REST API to generate notes and attach the same archives without introducing another packaging tool.

No CVE or deprecation establishing 2.4.0 as vulnerable was identified in this review; that is not proof of absence. Retaining 2.4.0 defers additional native hardening and must be revisited with encrypted-store and recovery compatibility coverage before expanding the release boundary. The catalogue snapshot records the newer release so further drift will trigger review again.

## Review trigger

Recheck this baseline when changing any dependency, SDK, runtime, runner image, GitHub Action, target framework, or packaging tool, before a supported release, and no later than the `Review by` date. The weekly security workflow compares current official .NET, Node, NuGet, GitHub Action, and runner-image catalogues with the reviewed catalogue snapshots and fails on a change; the packaging tool is supplied by the same pinned .NET SDK. It also fails after the review date rather than silently treating old evidence as current. A version change is a review signal, not an instruction to upgrade.

When a vulnerability, deprecation, or support change is found, block the pull request or scheduled check. Record the affected direct or transitive component, dated upstream advisory or lifecycle evidence, and the supported replacement. Update the central pin and every affected lock file together, then rerun locked restore, the repository gate, CodeQL, and the supported operating-system matrix. A clean vulnerability query is not evidence that an upstream component remains maintained.

Secret scanning and push protection were verified enabled through the read-only repository API on 2026-09-29. Recheck with `gh api repos/nullabletype/dot-orbit --jq '.security_and_analysis | {secret_scanning, secret_scanning_push_protection}'`; do not place an administrative token in a workflow merely to automate this read.
